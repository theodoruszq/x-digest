Replit's scaling laws for agent swarms: Opus 5.5 went from 3.7x to 18.9x with 32 agents — but the smartest solo model got worse past 8

@amasad·♥Likes: 288·Original·Nov 23, 20:52 UTC

We show that scaling the number of agents can yield dramatic performance gains, but unlike traditional scaling laws, more compute doesn't necessarily translate into better results, and how agents organize themselves matters.

- Given a fixed two-hour window, Opus 5.5 went from a 3.7x speedup on NumPy with one agent to 18.9x with 32 agents.

- GPT-6.2 Astra was the strongest solo agent but exhibited negative scaling beyond 8 agents.

- Models spontaneouslyadv. 自发地 developed different organizational structures. Decentralizedadj. 去中心化的 swarms scaled better than those that relied on centralized coordination.

- The parallelizabilityn. 可并行程度 of the problem was a strong predictorn. 预测指标 of swarm performance.

- Interestingly, individual model intelligence is a poor predictor of collective intelligence.

💡 任务是让 agent 优化 NumPy 的运行速度。实用结论：开很多 agent 并不一定更好，要看任务能不能拆开并行，以及 agent 之间怎么组织；“单个模型最聪明”不等于“团队最强”。他们还开源了评测集 Optimization-Bench。这是 Replit 自己的研究，未经第三方复现。
