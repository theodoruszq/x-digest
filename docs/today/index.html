Mitchell Hashimoto: Rex translates old API messages in about 35 microseconds

@mitchellh·♥Likes: 549·Original·Oct 19, 20:55 UTC

The latest Rex preview release includes a very important subsystem I've been working on for weeks to enable full forwards+backwards API compatibilityn. 兼容性 with clients and servers.

Every API change is a rule on a JSON pointer (RFC 6901). For each message, we compile all the rules between your version and ours into a trien. 字典树（前缀树） keyed by JSON path tokens. This happens lazilyadv. 惰性地（用到时才算） since we don't want a full quadraticadj. 平方级的 explosion …

Next, we wrote a custom recursive descentn. 递归下降（一种解析方法） streaming JSON editor (forward-pass only). If a key doesn't match any subtree in the trie, we fast-path copy the full value onto the wire …

Equal chains of changes are internedv. 驻留（相同的只存一份、大家共用） to the same pointer, so when we broadcast an event to many old clients, we translate it once per distinct chain, not once per client.

… an upgrade costs about 35 _microseconds_ on a 20KB JSON body.

💡 Mitchell 是 HashiCorp（Terraform）联合创始人、终端 Ghostty 的作者。Rex 是他正在做的项目，原帖没介绍它具体做什么，只说 Mac 测试又邀请了 1000 人，Linux 测试本周开始。值得学的是思路：把每次 API 改动写成一条"规则"，只改需要改的字段，其余原样复制，相同的改动链只算一次。注意他们现在才到第 4 版，1 万次修订是模拟出来的压力测试。
