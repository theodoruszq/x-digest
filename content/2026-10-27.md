> Prompt of the day:
> Split this "one-way door" PR into two:
> 1. A PR that implements everything, except it can be easily reverted (a two-way door)
> 2. A followup PR (stacked on top) that actually goes through the one-way door
> AKA expand/contract. Use feature flags as needed.
> Lets you [[de-risk|v. 降低风险]] a huge PR by testing large chunks of it in production first.
💡 "单向门"指做了就很难撤回的决定（比如删数据库字段、改数据格式），"双向门"指随时能撤回的。先把能撤回的大部分代码上线验证，最后再用一个小 PR 跨过那道"单向门"。可以直接复制给 coding agent 用。

> Skills and tool search can fix that without splitting context across agents. My rule of thumb is to keep a subagent when the work is parallel, needs fresh context or one agent really can't pick the right tools.

💡 据 X 新闻汇总，Anthropic 应用 AI 团队发现把子 agent 合并回一个主 agent 往往质量更好、更快更省，有客户提速约 2 倍。@RoundtableSpace 给了一段可直接用的体检提示词（♥296）："Read every subagent, skill and MCP tool in this project. Stop if any task gets worse."
