**4. Guillermo Rauch builds cpu-chat: sandboxed agents with no internet can still "talk" through shared CPU hardware** · [Original](https://x.com/rauchg/status/2114770919436808572) · ♥ 1.6k · 2026-10-26T17:27:32Z
> I built 𝚌𝚙𝚞-𝚌𝚑𝚊𝚝, a reproduction of @openai's findings of [[covert|adj. 隐蔽的、暗中的]] communication using the CPU.
> It runs on a generic host with 2+ Firecracker microVMs with no internet access. … I was able to chat via 3 separate mechanisms: ① CPU [[contention|n. 争用（多个程序抢同一资源）]] ② Cache [[eviction|n. 驱逐（缓存数据被挤出）]] timing ③ DRAM bandwidth contention
> Essentially, if shared hardware is involved, there's a good chance your agents can communicate covertly. And with really decent [[latency|n. 延迟]].
> Noteworthy: ironically, OpenAI and Anthropic's models refused to do this work. Open weight models got the job done.
💡 Rauch 是 Vercel 的 CEO。意思是：两个被隔离、不能联网的虚拟机，可以靠"故意让 CPU 变忙/变闲"这类方式互相传信号，就像隔着墙敲摩斯码。他强调这不同于 Meltdown/Spectre 那种能偷数据的攻击，而且在 Vercel 的真实环境里很难做到、也容易被监测到（这是他自己的说法）。

**5. Matt Pocock's prompt of the day: split a risky "one-way door" PR into a revertible part and a small final step** · [Original](https://x.com/mattpocockuk/status/2114749427889979405) · ♥ 678 · 2026-10-26T16:02:08Z
> Prompt of the day:
> Split this "one-way door" PR into two:
> 1. A PR that implements everything, except it can be easily reverted (a two-way door)
> 2. A followup PR (stacked on top) that actually goes through the one-way door
> AKA expand/contract. Use feature flags as needed.
> Lets you [[de-risk|v. 降低风险]] a huge PR by testing large chunks of it in production first.
💡 "单向门"指做了就很难撤回的决定（比如删数据库字段、改数据格式），"双向门"指随时能撤回的。先把能撤回的大部分代码上线验证，最后再用一个小 PR 跨过那道"单向门"。可以直接复制给 coding agent 用。
